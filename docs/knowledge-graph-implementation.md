# 对话知识图谱（第一版）

## 使用与成本

对话知识保留「列表 / 图谱」两种视图，默认列表，并只在当前浏览器记住选择。所有正式知识条目使用原有 UUID 作为节点，包括没有关系的独立条目。切换视图、查看节点和 GET 图谱快照不调用模型。

在选定收听的图谱中点击「生成关系」后，该记录才启用增量关系整理。入口说明将复用现有千问 Key 和 `qwen3.8-flash`，会增加调用和 token 费用。历史记录按需启用，不批量扫描其他收听。服务重启不读取或持久化 Key；恢复需要通过已有界面再次提供 Key。切回列表不会取消已经明确启动的任务。

节点详情复用已保存的简介、事实和引用。关系详情显示有方向的谓词、否定、计划、推测、时间、条件及转述出处；原文证据和最终译文可按句子 UUID 加载，包含列表第一页之外的句子。引用只表示对话中的陈述，不是外部事实核查，也不是音频回放。

## 数据与一致性

SQLite 从结构版本 5/6/7/8 迁移至 9；条目表不复制。关系、限定陈述、来源支持、修订和任务均随收听级联删除。迁移前应备份数据库；旧版本程序拒绝更高的结构版本，不能将应用回退描述成无条件兼容。

关系窗口以固定原文序号划分，附有限前文。关系抽取必须使用已入库候选 UUID，至少有一个属于当前窗口的关系依据。新节点、重复提及、别名和最终译文变更通过持久化脏窗口触发增量整理。暂时不足两个候选的窗口等待节点，不被视为已经穷尽关系。第一版每窗口最多 48 个候选；字节或候选预算不足会标记部分覆盖，保留所有可见节点，不宣称该窗口已穷尽关系。

输入快照包含最终原文、已经完成的译文和候选身份。节点简介和 `content_version` 不属于关系身份；无效 UPDATE、冗余提及导致的修订变化不能作废相同语义输入或重置重试额度。使用过的原文和译文参与指纹；请求完成时再次核对本轮状态、语义输入指纹、端点与记录。迟到、过期或已删除记录的结果不能覆盖新图谱。边、陈述和支持有确定性去重键；普通空输出不删除原有边。源版本失效只影响对应支持；更正保留原陈述与修订。

图谱快照同时返回节点、边和单调递增的 graphRevision。WebSocket 的 graph-invalidated 只触发合并读取；客户端按当前记录、请求代数和 revision 丢弃旧响应，不显示无节点的幽灵边。

## 调度与可靠性

关系使用独立、全局最多 2 个在途请求的队列（启动间隔仍至少 2 秒），并在实时翻译、知识整理或语音播报繁忙时让路。前台请求不会等待已经在途的关系请求结束。知识与关系对同一模型共享 Key 限流冷却；翻译模型的 429 不被扩大成所有模型的暂停。共享服务商仍可能存在账户层配额，不能保证真实供应商负载完全不受影响。

点击生成后持续处理所选收听全部符合条件的历史窗口，不设整轮 token、请求次数或运行时间上限。每个窗口在同一轮内累计最多尝试 3 次，即使输入变动使任务被替换也不重置；每次 HTTP 请求发送前原子登记尝试。单请求 30 秒硬超时，运输层不响应 AbortSignal 也会释放调度槽。请求开始时间、取消状态及每次尝试用量均持久化，重启不清空单窗口已消耗次数。前台等待、冷却和重试不再受整轮截止时间约束。自动重试遵守 Retry-After；配置/鉴权错误明确停止或等待 Key，耗尽单窗口重试次数的失败需要手动重试；部分完成结果是终态，输入未变化时普通手动继续仍复用已保存结果，不应重新进入自动空转。专门的失败/部分窗口重试入口需要独立费用确认，只重置这些窗口的本轮尝试上限；成功窗口和已有数据不变。一个窗口失败不取消其他仍可处理的窗口。

部分有效结果可以先保存，坏 JSON 或个别不合格关系不清空已经成功的图谱。服务返回的 token 用量与请求数用于实际用量记录；坏模型 JSON、过期或取消后的响应同样保存可用 usage，按原始尝试归属。缺失 usage 不伪造 token，不代表免费。界面显示已返回用量与未知用量请求数，不再显示虚构的 token 额度或预留预算；实际费用以服务商账单为准。单次模型输出长度上限以及输入窗口大小仍是请求级别的安全约束，与已移除的整轮限额不同。

取消 API 为 `DELETE /api/listenings/:id/graph`，先持久化终止状态再中断运行；旧响应不能复活旧轮或写入新轮图谱，已保存关系仍可查看。停止收听、切换视图或关闭网页不等同于取消关系。继续仅处理脏窗口和可重试失败；已完成或部分完成且输入相同的窗口复用结果。旧版本限额暂停任务和 v6 迁移暂停任务仍可显式继续；新任务不会因整轮 token、请求或时间阈值暂停。

客户端在生成或取消成功、失败和响应超时后均显式 GET 对账，不以同 ID 的 select 当作刷新，也不会自动重发 POST/DELETE。确认服务器状态前禁用重复生成。进行中的图谱每 2 秒只读轮询，单次 GET 最长 10 秒、同一时刻仅有一个读取；临时读取失败按 4/8/15 秒退避，进行中的工作持续重读直至读到终态。非进行中读取最多额外重试 3 次，最后一条失效通知读取失败也会重试。收到完成、失败、部分完成、取消或历史暂停通知时，先隔离旧请求并读取最终图谱，读取确认前不宣称当前零条就是最终结果；同一终态通知合并。读取最终快照或缺少 Key 后停止自动轮询；恢复联网或页面重新可见时只读对账。切换记录、取消和销毁时丢弃迟到响应并清理相应计时器。

当前关系协议为 [v3](relation-evidence-contract.md)：模型一次判断原文语义，服务端只校验同记录端点、支持的关系字段、当前窗口证据、名称身份及原文版本完整性。服务端保存完整原文片段及准确位置，模型无须生成 quote、偏移或身份 mention ID。名称及限定引用兼容大小写、全半角、空格和常见标点差异。已移除中英文动词字典、重复的跨句指代规则及基于词序的语义否决；语义准确性依赖模型，结构校验不能证明任意自然语言关系。没有可靠关系、只共现或指代不明确时应省略关系，空结果或候选过滤都正常完成。只有输入覆盖不完整或入库问题才是 partial；请求、解析、输出截断等真实问题仍是 failed。

## 验证边界

所有自动测试使用固定数据和本地模拟 ASR/MT/TTS/关系服务，不发送真实 Key，不调用付费模型。覆盖静态长历史一次启动跨越旧整轮上限完成、无效 UPDATE/简介修改去重、实际身份变化保留、迁移、幂等、重启保持单窗口尝试次数、仅新增引用、迟到翻译与节点、在途删除、部分失败、关系限定、桌面/移动端详情和分页外引用。浏览器脚本检查列表/图谱切换、偏好、搜索、缩放、键盘、关闭后焦点、切换记录的迟到响应，并保留截图。`scripts/verify-relation-progress-browser.mjs` 另覆盖超过 2 分钟和 12 次请求后的诚实进度、未知 usage、生成响应丢失与 GET 失败恢复、无通知时轮询至部分完成、失败重试入口、取消响应丢失、联网恢复及终态停止轮询，且不重复提交生成。

本地干扰测试只证明被挂起的关系 HTTP 请求不会阻塞字幕和模拟语音处理，不代表真实模型准确率、真实 provider 配额、真实首音或端到端性能基准。真实费用和语义质量仍需实际使用采样后评估。


## 关系整理吞吐优化

- 已使用 `qwen3.8-flash`，直接 HTTP JSON 明确传 `enable_thinking: false`；不切换供应商或臆测旧模型更快。官方依据：[当前模型](https://platform.qianwenai.com/docs/developer-guides/getting-started/latest-model)、[Chat API](https://platform.qianwenai.com/docs/api-reference/chat/openai-chat)、[延迟优化](https://platform.qianwenai.com/docs/developer-guides/run-and-scale/latency-optimization)。
- 模型只接收本次请求内的短节点/句子/断言 ID，删去服务器使用的 UUID、hash、监听及窗口版本元数据。原文、已完成译文、名称/别名、身份可信度、更正目标与事实限定不裁剪；返回结果先按短 ID 白名单校验，再还原为持久 ID，用原始快照和全文 revision 再校验。已有完成窗口的指纹不变，不因传输优化重新付费。
- 结构化输出使用 `response_format: json_object`；输出上限保持 6000，用官方支持的 `max_completion_tokens`。`finish_reason:length` 明确计为失败，保留 usage，不把截断当完成或用相同预算自动重试。
- 独立窗口可并行；显式更正形成源顺序屏障，先等前面的窗口提交，再使用已存在断言，更正完成前也不启动后面的窗口。SQL 事务仍在 HTTP 前原子登记单窗口尝试与整轮实际请求计数，取消中断所有在途槽位；整轮没有到期中断。
- `test/relation-throughput.test.mjs` 的固定 25 秒模拟服务中，4 个窗口全部完成由串行 100 秒变为双并行 52 秒，两者都恰好 4 次调用并保留全部证据，没有靠超时停止。代表性 9 句/24 候选的传输体从 11,227 字节降到 6,436 字节（42.7%）。这些只是可重复的构造测试，不能宣称真实供应商也加速 48%；真实延迟和质量需另行获准采样。

## 零关系诊断与显式恢复

每个成功解析并提交的任务持久化模型返回行数、结构与证据校验后行数、最终接受行数、新增唯一边数和复用已有边的行数。过滤原因保留用于诊断；候选过滤不等于任务失败，入库问题仍需单独处理。默认折叠的「整理详情」按每个窗口最新任务汇总，避免把反复重试累加成当前结果；存储总数/可见关系则是当前整张图。新增边与复用边按边身份去重，复用仍可能新增限定陈述或支持。可见关系包含 active 与 needs_review，搜索和类型筛选还可进一步减少画面连线。

旧任务无法精确还原返回和接受数量；迁移保持 NULL。未解析、失败和进行中的窗口也不猜测模型返回数。已保存 rejected_json 可仍汇总为已知拒绝数量及原因。固定错误码白名单映射为中文说明，未知码只显示 UNKNOWN_REASON；诊断不包含标题、原文、quote、模型输出、节点名或 Key。输入范围受限单独提示，不能声称已穷尽全部关系。

可在服务器本机运行 `node scripts/diagnose-relations.mjs /path/listenings.sqlite [listening-id]`。脚本仅只读打开 v8+ 数据库并输出不含原文内容的数量/错误码汇总，不导入 ListeningStore、不迁移、不请求模型、不修改数据库。未提供 ID 时选最近启动关系整理的收听；输出不会包含实际 ID。

`POST /api/listenings/:id/graph` 的默认动作仍是生成/继续；专门恢复请求使用 `{key, retry:"failed_partial", expectedEpoch}`。服务器只选 failed/partial 窗口，在事务内核对 epoch 且禁止并发未完成任务；过期或重复确认返回 409，前端只读对账不重发。新轮每窗口仍最多 3 次，保存 min_result_epoch 使显式选择的旧 partial 可再处理，但普通刷新、迁移、重启或普通继续不能绕过缓存。取消仍挡住迟到结果。该功能只恢复真实未完成工作；已经正常完成但没有可靠关系的窗口不需重试。启动时会将仅因候选过滤而 partial 的旧结果标为 complete，不重新请求模型，也不改变已保存关系和历史未知数量。
