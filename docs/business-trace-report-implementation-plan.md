# 业务追踪报告实施方案

日期：2026-10-04。基线：PR #49 合并后的 main。本文先入库，再按下列任务实施。报告分析不调用模型，也不增加业务模型请求。

## 1. 问题与目标

真实报告展示了311条事件、88个步骤，但用户难以判断业务工作量、活动状态和异常位置。当前 `scripts/trace-report-view.mjs` 只按步骤前缀分组，首屏以 UUID 和技术调用树为主。`src/server/diagnostics/report.ts` 将缺少终态与证据异常汇总为 unknown。两者需要分开解释。

本次交付让用户先看到识别、翻译、知识整理、关系提取、播报五个业务区，再按用途、业务任务、调用和事件逐层下钻。每条洞察必须对应实际证据。缺失数据不可补成成功、零工作量或正在运行。

| 任务 | 实现 | 验收 |

## 3. 统计契约

- 五域固定存在。无事件时显示“未观测到”，不解释为未启用、未触发或零工作量。
- 业务对象按进程、收听、步骤类别和 job 标识归并。同一知识/关系 job 的继续执行保留所有执行实例，状态摘要取该对象最后一个实例，并显示历史异常数量。
- 播报单元与播放会话分开计数；不把二者相加当作已播句数。短句翻译归翻译域，以用途说明它服务于提前播报。
- 调用尝试只统计 knowledge.http、translation.http、relation.http、speech.http、speech.stream。连接、根任务、抽取包装不重复计数。该数不是计费请求数，旧日志的调用步骤可能包含准入等待。
- 累计调用耗时只累加有有效起止记录的上述调用步骤。它表示观测到的调用区间累计值，包含旧埋点可能包含的等待，不是整次任务墙钟时长或模型纯计算时间。识别长会话不参与此比较。
- 父步骤未归因耗时：父耗时减去直接子步骤区间的并集。要求父子边界齐全、区间合理；不把并行子步骤重复相加。结果仅标记“未由子步骤覆盖”，不能自动归因为排队、数据库或 CPU。
- 结果接受/拒绝按每次明确 checkpoint_committed 事件统计，是处理次数，不冒充最终唯一知识条目或图谱边数。缺计数时显示未记录。
- 句子编号仅使用真实 sequence_no；无编号时用短 ID 区分，并明确不是业务序号。关联事件表示某批次使用了该句，不等于严格因果边。
- token、成本、完整队列积压不在缺少可靠来源时推算。本次不展示虚构金额、百分比进度或全任务完成率。

## 4. 活动与证据契约

报告是离线快照。最近活动显示事件时间与“最后记录”，不使用当前时间制造运行中动画。已有终态直接展示；没有终态显示“未观察到结束”。局部起止缺口和全局采集缺口分别提示。整体无完整结束清单时，所有累计指标都是已观测值。

业务任务失败、请求曾失败但业务后来完成、明确取消、正常空结果必须区分。播报的音频生成与客户端消费反馈分别展示；播放反馈缺失只形成证据提示，不断言扬声器未发声。

## 5. 界面与洞察

首屏：当前收听范围与采集质量、五域总览、需要关注的问题。业务区显示对象数、调用尝试、已完成/失败/继续处理/取消/未见终态数量和最近活动。点击业务区进入用途与任务列表；支持从语音单元跳转到同句翻译及知识/关系任务。调用树、原始事件、时间线和双版本对比保留为进一步下钻工具。

面积变化容易导致位置跳动，本次采用固定区域与同尺度工作量条；切换次数或累计耗时后重算所有区域的同一比较尺度。大块的位置稳定，颜色表示状态，条长表示选定指标，不混淆两者。

规则输出分为明确异常、需要检查、证据不足。慢调用阈值为诊断规则，不宣称服务 SLA；同类样本太少时不输出统计性异常结论。未归因耗时达到2秒且占父耗时40%以上才提示。取消后的播放反馈缺失不作为播放故障报警。

## 6. 兼容、安全与范围边界

保留 schema v1 的允许列表导入和脱敏导出；扩展元数据时升级埋点版本。旧字段缺失不补造。所有文本仍通过 textContent 渲染，离线 CSP 禁止外部网络请求。报告导入不信任已有聚合结果，重新从事件计算。

本次不新增实时监控服务、自动日志持久化、完整队列生命周期、时间游标回放、计费估算或同输入回归判定。它们是后续独立任务，不能将本次离线报告描述成实时系统。原调度优先级、重试预算、数据库协议、PCM 协议和应用版本保持不变。

## 7. 验证与记录

纯计算测试覆盖多次执行归并、并行区间并集、未知状态、缺域、损坏日志、结果计数、取消/恢复和脱敏。集成测试运行真实应用、Effect、SQLite、HTTP/WS 适配器，仅以本地服务替代付费模型。浏览器测试覆盖总览到事件、用途筛选、句子关联、旧版对比、导出、移动端与无网络请求。

实施后的实际结果在本节补充，不在验证前预填通过结论。
