# 知识编辑版本兼容

旧版以 `sha256(JSON.stringify({item, segments}))` 生成 revision，`item` 包含整行和显示字段。数据库 v11 升到 v12 时新增覆盖名称列和 `display_name`，即使内容不变，编辑、删除和名称校正仍会误报 409；按旧 revision 查询的失败记录和结果缓存也会失效。

## 固定投影

`knowledge-revision.mjs` 定义独立于数据库结构的版本 1 内容投影；GET 返回 64 位十六进制 `revision` 和 `revisionVersion: 1`。投影包含身份、摘要、类型、标签、策略及内容版本、覆盖名称及身份依据、别名、引用、事实、修订，以及关联段落的原文、译文、翻译状态和定位字段。字段按固定顺序建立，数组按内容排序。

新增列、显示字段、对象键顺序、查询行顺序和时间戳变化不影响 revision。原始名称、覆盖名称、内容、引用或原文/译文变化仍改变 revision；校验不限于 `content_version`。未来修改投影语义必须增加版本并提供兼容策略。数据库结构保持 v12，无额外迁移。

## v11/v12 兼容边界

服务端以当前数据按冻结的两份历史字段及键顺序重新计算指纹，仅当客户端 revision 等于当前固定投影或历史重算值时允许操作。v11 指纹还要求两个覆盖名称列均为空。兼容读取不改库、不调用模型、不改变原有 UUID 输入指纹；事务提交阶段仍重新校验当前固定投影。

因此升级前打开、内容未变的面板可直接保存或删除；真实修改后的旧面板仍不能写入。历史指纹包含时间戳及原查询顺序，如果这些信息也变了，兼容不能证明内容相同，仍安全拒绝。兼容仅覆盖已发布的 v11/v12 口径，不从客户端推断或放宽任意版本。新客户端只获得固定投影指纹，历史桥接可在确认旧页面和旧缓存均不再使用后单独移除。

名称校正缓存同时查当前及历史上下文指纹，已有 corrected、unchanged 和 insufficient_evidence 结果可继续复用，不增加模型请求。新名称任务在既有 `result_json` 中持久化输入 revision 别名；相同输入的旧、新面板合并后，即使名称已改变或服务重启，响应丢失的客户端仍可只读找回 accepted job ID。内部别名不出现在公开结果中，不影响 UUID 原始输入校验或请求预算。

## 冲突与失败恢复

真实版本冲突响应为 `409 {code: 'KNOWLEDGE_EDIT_STALE', saved: false, error, revision, revisionVersion: 1}`。其他忙碌、运行状态及幂等冲突保留原语义。服务端记录 `knowledge_revision_conflict`，仅含收听 ID、条目 ID、操作和当前/提交摘要前 8 位；不记录原文、草稿、Key 或完整摘要。

前端收到此 code 后只发 GET：人工编辑保留输入、展示最新名称和引用原文/译文，重新隐藏删除确认；用户再次点击才发起保存或删除。名称校正展示最新名称并等待明确重试。读取失败时阻止继续写入，要求重开核对。不能直接用返回的新 revision 自动重试写入，否则会绕过真实并发保护。

人工任务返回最近一次未完成/失败记录；最近一次成功后不再显示更早的失败。名称校正同样优先显示最近的运行/失败任务，成功结果仅在上下文有效时显示。失败任务附带 `staleRevision`；真实过期的人工任务不预填旧名称或自动生成，未保存事实和旧错误仍可查看。历史口径相同内容不被标记为真实过期。

## 回归验证

`test/knowledge-revision.test.mjs` 覆盖新增列/显示字段/行序、真实 v11 数据库迁移、保存/删除/名称校正、旧收据幂等、旧结果缓存、合并任务的多口径恢复、失败可见性、安全日志和无模型调用的冲突。浏览器夹具验证草稿保留、只读刷新、再次删除确认、过期失败展示，以及旧面板兼容。全部使用临时 SQLite 和本地模拟 provider，不读取用户数据库，不请求真实付费模型。
