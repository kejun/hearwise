# Revision normalization verification (KEJ-68)

This verification-only profile covers the revision-v1 normalization part of HW-06.
It does **not** establish full HW-06 acceptance, concurrent-editor behavior (KEJ-69),
name-replacement intervals (KEJ-70), SHA-256 injectivity, or full-application correctness.
No production file, public API, database schema, or runtime dependency changes.

## Run and reproduce

Use Node 24 and the checked-in `verification/lean/lean-toolchain`:
`leanprover/lean4:v4.35.0`, Lean commit
`eb6cafb7290e8bd5f2937522d8d804f58f02bafc`. Lake is the bundled
`5.0.0-src+eb6cafb` (Lean 4.35.0); only bundled Std/Lean libraries are used,
with no Mathlib or downloaded Lake dependencies.

```sh

```

The installer downloads the official [Lean 4.35.0 Linux release](https://github.com/leanprover/lean4/releases/tag/v4.35.0),
SHA-256 `7289597a44543246c9227b8cae501767e095ce17f6d448b95fc4a8dc97268f6d`.

## Input domain and exact wire mapping

`knowledge-revision.mjs:knowledgeRevision` is the unchanged public implementation.
`Revision.lean:normalize` defines the version-1 projection. It preserves object
field order and sorts **serialized JSON UTF-16 code-unit sequences**. It never uses
Lean String ordering, Unicode code-point ordering, locale collation, or Lean Json
serialization for business strings. Multiplicity is preserved: arrays are multisets,
not sets. Object property insertion order outside the explicit projection is ignored.

The executable differential domain is:

- Plain, side-effect-free snapshot/row objects. No getters, proxies, `toJSON`, cycles,
  symbol keys, or prototype-dependent business fields.
- Required `item` object and `segments` array; child collections are arrays or
  missing/null. Missing/null child collections become empty arrays. Aliases contain
  strings; child rows have scalar business fields.
- Scalar business fields are UTF-16 strings (including unpaired surrogates), booleans,
  null/missing/undefined, or exact JavaScript safe integers from
  −9007199254740991 to 9007199254740991. Signed zero normalizes to decimal `0`.
- Missing/undefined **business fields** normalize to null. Empty string, false, and
  zero remain distinct from null. No implicit trim, Unicode normalization, or
  case-folding is performed.
- JSON strings use short escapes for quote, backslash, backspace, tab, LF, FF, CR;
  other controls and lone surrogate units use lowercase `\uXXXX`. Valid surrogate
  pairs remain pairs. Non-ASCII and U+2028/U+2029 remain unescaped.
- Integers use exact decimal notation. The safe-integer interval never needs
  exponent notation. Fractional/unsafe/nonfinite numbers are outside the proof
  bridge. Separate implementation tests preserve fractional behavior, JSON's
  nonfinite-to-null behavior, BigInt rejection, and ignored complex extra columns. SQLite's INTEGER affinity
  does not guarantee integer values: fractional/unsafe begin_ms/end_ms remain
  explicitly outside this proof bridge and have independent public-function
  regression comparisons.

Lean's abstract scalar model permits arbitrary integers and natural-number unit
lists; the executable parser restricts units to 0..65535 and integers to the safe
interval. General invariance theorems apply to this broader abstract model, but
JavaScript correspondence is claimed **only for the declared executable domain**.
Transport uses tagged scalar ASTs and arrays of code units, so Lean's Json parser
cannot replace unpaired surrogates. `ascii` only serializes fixed ASCII keys and
integer decimal strings. Unrecognized row keys are ignored by the projection.

The versioned independent contract in `verification/revision/corpus.mjs` and Lean
contains these exact fields, in this order:

- Item: id, listening_id, type, canonical_name, normalized_name, dialogue_summary,
  background_note, certainty, display_label, short_description, policy_version,
  content_version, name_override, name_override_identity; then aliases, mentions,
  revisions, facts
- Segment: id, listening_id, run_id, sequence_no, asr_sentence_id, original_text,
  translation_text, translation_state, begin_ms, end_ms
- Mention: item_id, segment_id, surface_text
- Revision: id, item_id, action, old_value, new_value, merged_from_id, reason
- Fact: id, item_id, segment_id, surface_text, content, certainty

The root key order is version, item, segments. Current timestamps, derived display
name, and future unrelated columns are excluded. Forty separate scalar-field
mutations ensure every declared scalar business field changes the tested preimage
and observed public digest. The original fixed current-version golden digest is
also retained by `test/knowledge-revision.test.mjs`.

## Proved statements and assumptions

All theorem names below are in `Hearwise.Revision`. No theorem assumes hash
injectivity or turns equality of a digest into equality of arbitrary inputs.
`normalize` returns the complete serialized UTF-16 sequence before hashing.

| Theorem | Exact premise and conclusion | Implementation mapping |
| --- | --- | --- |
| pick_irrelevant | For each key in the fixed list, nullish-normalized values agree; picked ordered fields agree | `pick` |
| missing_equals_null | Absent scalar and explicit null normalize equally | `row[key] ?? null` |
| canonical_permutation | Lists of serialized unit sequences are `List.Perm`; sorted outputs are equal | `ordered`, serialized `<`/`>` |
| canonical_preserves_multiplicity | Canonical sorted list is a permutation of its input | `ordered` does not deduplicate |
| row_irrelevant | Rows agree on the listed business fields; serialized row outputs agree | picked child rows |
| rows_irrelevant | Pairwise corresponding rows agree on business fields; mapped row serializations agree | child-row projection |
| normalization_equivalent | Item fields agree; each serialized child collection is a permutation; complete normalization agrees | full `knowledgeRevision` preimage |
| normalization_permutation | Same item row, and aliases/mentions/revisions/facts/segments each permuted; normalization agrees | all current array permutations |
| normalization_irrelevant | Same aliases; item and pairwise child rows agree on listed fields; normalization agrees | unrelated fields on every row kind |
| row_missing_null | Replacing a selected field by absence or explicit null yields equal row serialization | nullish field normalization |

`Equivalent` is an explicit relation, not a hidden assumption of whole-output
equality. The permutation and irrelevance corollaries separately discharge its
premises from raw collection permutation and row-level field agreement. Sorting
uses Std's proved merge sort, with transitivity, totality, and antisymmetry of
lexicographic natural-number lists supplied in the proof.

`AxiomAudit.lean` uses `#guard_msgs` around `#print axioms` for **every** theorem.
The checked transitive dependencies are:

- `missing_equals_null`: none
- `pick_irrelevant`, `canonical_preserves_multiplicity`: `propext`, `Quot.sound`
- All remaining theorems: `propext`, `Classical.choice`, `Quot.sound`

These are Lean's standard logical axioms. No custom axioms, unfinished proof
placeholders, or native-evaluation proof shortcuts are accepted. A changed axiom
set fails the exact guarded audit. The kernel checks the proof terms; compiled
oracle execution, compiler/runtime, adapters, Node/SQLite and hashing remain in the
implementation-testing/trusted-tool boundary. See Lean's
[proof-validation documentation](https://lean-lang.org/doc/reference/latest/ValidatingProofs/).

## Differential and legacy scope

The fixed profile runs **662** cases: 25 boundary cases, 40 field-participation
cases, 80 missing/null cases, 256 seeded snapshots, their 256 independently permuted
and extra-field variants, and 5 actual SQLite snapshots. It checks 298 equivalence
pairs. One boundary input covers every UTF-16 code unit in separated chunks;
this finite sweep tests the serializer and does not prove equivalence to
ECMAScript for arbitrary strings. Additional cases cover valid/lone/misordered surrogates, supplementary-vs-BMP sort
order, combining characters, controls, integer boundaries, falsy values, and
missing/null/empty child arrays.

For each case:

1. The compiled Lean definition returns the serialized UTF-16 preimage.
2. It must exactly equal an independent JavaScript contract serialization.
3. SHA-256 of that preimage must equal the unchanged public `knowledgeRevision`.

The third check is an observed digest comparison, **not a mathematical proof that
SHA-256 never collides**. The first two compare actual preimage units directly.

The real SQLite cases reuse `ListeningStore.knowledgeEditSnapshot` and the existing
`seedGraphListening`: initial snapshot, populated revision/fact history, added
unrelated columns, reopened database, and changed source timing. Synthetic IDs and
facts are used, and each database is removed in both worker and parent cleanup.

Legacy v11/v12 are deliberately **not** Lean permutation-invariance claims. Existing
`preFixRevision` independently reproduces the frozen historical object/SQL query
ordering. Tests show timestamp and history-query-order changes alter legacy tokens
while leaving the current projection unchanged. Both name-override fields, including
empty but non-null strings, prohibit v11 compatibility. The existing 8 regressions
also exercise real v11 migration, old receipts, v12 caches, stale edits, deletes,
and HTTP conflict metadata without paid calls. The runner clears inherited
`NODE_TEST_CONTEXT`, selects TAP, and requires at least 8 actually executed tests,
all passing with no skips/cancellations; an exit-0 empty suite cannot pass.

Three isolated copies of the actual production module are mutated: omit
background_note, reverse serialized sorting, and use falsy fallback instead of
nullish fallback. Every mutation must disagree with its reference witness. The
production file is never patched. The module source and exact witnesses are bound
by digests in the result. No failure is solved by lowering sample counts or budgets.

## Evidence boundaries and failure behavior

Dedicated IDs HW-06-02..05 and their methods are defined in
`verification/revision/profile.mjs`; the existing single-scenario pilot schema is
not reused or mislabelled as a proof. Integration into the project-wide release
selector remains the later release-gate work. This report explicitly keeps
`fullProjectAcceptance` and `fullHW06Acceptance` false.

Every stage has a process-group watchdog: tool versions 15 seconds each, proof
build 120 seconds, axiom audit 30 seconds, differential 90 seconds (oracle 60),
and legacy regressions 90 seconds (individual Node tests 30 seconds). The whole
runner has a 360-second deadline applied to each remaining stage. The installer
has a bounded 600-second transfer timeout and CI has a 10-minute job timeout.
Interrupted/timed-out groups are terminated, temporary databases/mutants are
removed, and already-written diagnostics remain available.

Missing tools, wrong versions, failed builds, changed source/profile, incomplete
or interrupted execution, missing/changed artifacts, missing differential samples,
and undetected mutants cannot pass. `test/verification-revision.test.mjs` injects
these report defects and proves the gate rejects them. A successful development
run on dirty source remains a development result; only a clean committed source
can pass `--release`. Report completion and each command's exit status must both
be checked; a log line containing a successful test is insufficient.
