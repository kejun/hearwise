# 本地执行追踪报告

## 当前能做什么

将 Hearwise 已采集的知识任务事件转成一个离线 HTML 文件。用浏览器直接打开，无需启动报告服务器，也不会访问第三方服务。

报告支持以下操作：

- 按“收听记录 → 知识流程 → 执行批次 → 调用步骤 → 事件证据”逐层展开。调用步骤可以继续展开到抽取、修复和 HTTP。
- 各分支独立展开、折叠。筛选后清空输入，恢复之前的展开状态。
- 查看成功、失败、部分成功、取消、等待后续执行及未知状态。父调用成功时仍保留失败的子调用，不覆盖异常证据。
- 按步骤、任务 ID、状态或安全错误码查找；从节点详情的路径按钮返回上层证据。
- 查看按进程分组的时间线；查看两次执行的步骤路径、次数和状态差异，并打开任一版本的证据。
- 导出脱敏的 JSON 证据包，供后续再次生成报告或作为人工选定的对比基准。

这份报告目前覆盖知识执行、提取、修复、HTTP 及检查点事件。翻译、关系提取、播报和浏览器消费尚未接入，不能将“知识步骤全部结束”理解为整次收听任务完成。

## 不调用模型，先体验报告

需要 Node.js 24 及已安装的项目依赖：

```bash
npm run trace:demo
```

命令输出 HTML 的绝对路径，文件位于 `data/diagnostics/example-*/report.html`。直接用浏览器打开。

示例运行真实的 Effect 运行时、SQLite 知识工作流和 HTTP 适配器。模型服务由本地 fixture 替代，包含正常完成、HTTP 429 后由测试代码恢复及删除取消。恢复场景仅用于验证报告保留异常历史，不代表业务已新增自动重试。示例数据不是用户的生产记录。

## 用一次实际执行生成报告

先启用采集，再执行需要排查的收听任务。macOS / Linux 可使用：

```bash
HEARWISE_TRACE=1 npm start > /tmp/hearwise-execution.log
```

任务完成后停止服务，再执行：

```bash
npm run trace:report -- /tmp/hearwise-execution.log --output /tmp/hearwise-report.html
```

报告程序只提取 `execution_trace` 记录，其余日志不进入报告。原始服务日志可能包含其他模块的输出，不应作为脱敏文件分享；分享生成的报告或证据包。

输出文件必须尚不存在。程序拒绝覆盖已有文件，避免改写原始输入或已认可的基准。输入限制为 20 MiB；最多保留 10,000 条待分析事件，超过事件上限明确标记不完整。日志过大时先按一次诊断采集范围整理；任意截取的片段不能用来断言步骤没有执行。

支持三种输入：服务端混合日志或事件 JSONL、`runtime.diagnostics()` 快照、报告导出的 `hearwise-trace-report/v1` JSON。导出包同时有本次和基准数据时，重新导入采用“本次”数据。

## 对比两次执行

```bash
npm run trace:report -- /tmp/after.log --baseline /tmp/before.log --output /tmp/compare.html
```

也可以将人工选定的导出 JSON 传给 `--baseline`。程序不会更新或覆盖基准。

匹配键是由明确父子关系组成的步骤路径，例如 `knowledge.execute → knowledge.extract → knowledge.http`。随机生成的 span、trace 和 job ID 不参与路径匹配；对比行会保留两次执行各自的实例列表，支持继续下钻。

当前对比是**已观测步骤的聚合对比**。它可以提示调用次数或状态变化，但尚不能证明变化由 AI Coding 导致。输入、模型、提示词、配置及重试条件可能不同。未观测到的步骤不等于没有执行；埋点版本不同会单独提示。固定输入基准、业务不变量的 CI 阻断、依赖边及并行度变化检测仍属于 O06 后续任务。

## 如何解释状态与完整性

| 显示 | 含义 |
| --- | --- |
| 成功 | 该次调用结束成功，且已观察到的子步骤没有未解决异常 |
| 成功 · 存在异常子步骤 | 父调用成功，但子步骤曾失败、取消或恢复；展开可查看原始尝试 |
| 部分成功 | 业务明确返回 `partial` |
| 失败 | 调用失败，或业务明确返回 `invalid`；并不保证能从追踪确定根因 |
| 已取消 | Effect 中断终态；事件中可查看已记录的取消原因 |
| 等待后续执行 | 当前执行返回 `continue`，业务任务仍需调度；本次调用结束不等于整个任务完成 |
| 未知 / 未结束 | 起止证据不足、子步骤未结束或结构异常，不推断成功或跳过 |

仅在快照声明采集开启、无丢弃、无活动 span，且导入检查也没有发现异常时，报告显示“当前进程缓冲完整”。此状态仍限于当前埋点范围。

普通日志没有结束清单，即使所有已见调用都有终态，也显示“完整性未知”。序号缺口、截断行、父节点缺失、循环、冲突重复、多个构建版本或快照进程不符则显示“不完整”。相同事件的重复投递按事件 ID 去重，冲突重复不能悄悄覆盖。

父子连线只表示执行归属，不表示兄弟节点之间的因果依赖。时间线位置取墙钟时间，步骤耗时取 Effect 的单调时钟；不跨进程同步时钟、不累加并行耗时，也不推断关键路径。等待理由、跨分支影响范围及完整关键路径有待更完整的业务事件支持。

## 数据与部署边界

- 报告入口是本地命令，不增加公开 HTTP 诊断接口。
- 导入时按版本、步骤、事件名、属性和错误码的允许列表重建数据，不复制任意 `message`、模型输出或额外字段。
- HTML 用 `textContent` 显示数据，内嵌 JSON 转义 HTML 特殊字符；内容安全策略禁止网络连接，执行脚本通过固定内容哈希授权。
- 业务 ID 仍会保留用于定位。若人工把敏感文本作为业务 ID 输入，即使符合 ID 格式也无法自动识别，分享前应检查。
- 节点、时间线、差异实例及事件按每页 50 项显示；子树和事件正文按需创建。文件本身包含完整的有界证据数据，并非服务端分页查询。
- 当前文件由操作者自行保留和删除。自动轮转、独立持久化存储、查询服务、完整采集清单及页面内实时诊断尚未实现。

实现依据：Effect 的 [span 和父子追踪模型](https://effect.website/docs/v4/observability/tracing/)。项目总体迁移与后续验收见 [实施方案](effect-migration-implementation-plan.md)。
