# 统一名称纠正（KEJ-37）

列表和图谱节点详情只提供「纠正名称」。当前写法只读，正确名称可编辑。手动填写或获取校对建议后，都通过同一个「保存纠正」提交。Deebo → Tibo 可直接保存，即使 Tibo 尚未出现在原文或译文中。

## 保存范围

手动保存新增模型请求为 0，不需要 API Key。服务端从当前条目读取原始 `canonical_name`，只在其关联段落中做完整词语替换。英文忽略大小写但保留单词边界，中文和正则特殊字符按字面匹配。未关联段落、其他收听和已有译文保持原值。

实际名称、规范化名称、对应别名、简介、摘要、事实文字和引用在同一事务提交。只替换已有文字，不生成新内容。已有显示覆盖在保存时清除；条目和事实 ID 保留。同名条目冲突明确拒绝，不合并身份。纠正规则仍按收听保存，继续收听时沿用新写法；不会新增锁住整张卡片的人工内容规则。

关系端点、断言和引用 ID 保留。关联段落的全部有效关系引用同步更新原文摘要、引文和 UTF-16 位置，包括属于其他节点、位于错误词之后的引用；已失效的历史引用不会复活。断言只替换对应文字并更新去重摘要。窗口和既有请求记录不重开，不重新整理关系。

本地替换复用 `knowledge_edit_jobs` 的手动回执，`result_json.kind=name_replace` 区分于旧重新生成。运行中回执和成功状态只存在于同一事务；失败整体回滚，重启不会遗留半次替换。关系触发器仅在这个事务中让本地替换维护引用；普通原文、身份和别名变更仍使关系失效。启动时安装当前触发器，数据库结构版本保持 12。

## 校对建议与并发保护

自动建议需要 Key，每次用户明确点击最多发起一次 `qwen3.8-flash` 请求，关闭 thinking，超时 30 秒。复用有界上下文：输入 JSON 最多 8000 个 JavaScript 字符、最多 6 段关联原文、已有译文及空间允许的相邻段落。结果只有名称和理由，不写库、不留后台 Key、不自动重试。名称可以尚未出现在原文中，因为仍需人工确认。失败保留草稿，并允许手动保存。

保存沿用固定字段 `revision` 与 v11/v12 兼容校验。真实冲突返回 `KNOWLEDGE_EDIT_STALE`；页面只读取最新名称、关联原文和译文，保留草稿，等待再次点击保存。删除同样需要重新确认。活动收听、未完成翻译/知识任务、正在保存的旧任务及在途关系任务会阻止写入。

UUID 幂等键绑定条目、目标名称和提交版本。同键同输入读取已提交回执，同键不同输入拒绝；响应丢失时前端只查回执。旧卡片重新生成和显示覆盖校对 API 保留兼容，当前界面不发起它们；旧失败记录仍可读取，旧在途任务不自动重试。

| API | 行为 |
| --- | --- |
| `POST /api/listenings/:id/knowledge/:itemId/name-replacements` | `{name,revision}` + UUID `Idempotency-Key`，同步返回条目和成功回执 |
| `POST /api/listenings/:id/knowledge/:itemId/name-suggestions` | `{revision,key?}`，只返回 `{suggestion:{name,reason},revision}` |
| `GET /api/listenings/:id/knowledge/:itemId/edits/:jobId` | 只读查询持久化保存回执 |

## 回归验证

`test/knowledge-name-replacement.test.mjs` 使用本地数据库与模拟 provider 验证实际替换、引用与关系一致、ID 保留、幂等、回滚、升级兼容及模型请求次数。现有编辑、名称校对与 revision 测试继续覆盖旧 API。

默认浏览器验收中的 `knowledge-edit`、`knowledge-name`、`knowledge-revision` 覆盖无 Key 的 Deebo → Tibo、可编辑建议与明确确认、代理响应丢失、并发草稿保留、删除确认和桌面/390px/320px 布局。全部使用夹具，不调用真实付费模型。
