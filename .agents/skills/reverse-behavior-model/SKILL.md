# 还原现状行为模型

先完成一条流程。用中文业务动作命名，保留技术原名。每次新的分析创建独立报告，保留已有报告。默认只读分析，不修改代码、运行生产任务或调用付费模型。

## 1. 确定输入与版本

- 确认流程名称、入口（接口/消息/定时任务）、相关代码范围、日志路径及时间窗口（含时区）。可从当前请求和仓库推导已知项，只询问真正缺失的输入。
- 阅读项目 AGENTS.md；记录仓库 HEAD、工作区修改、分析时间以及日志中的构建/埋点版本。依项目约定获取最新代码，不覆盖用户改动。
- 确认实例关联字段（如 listening_id、run_id、job_id、trace/span ID）和字段作用域。不要把同一收听中的多个任务当成同一实例。
- 先读取 [Hearwise 证据入口](references/hearwise-evidence.md) 定位文件，再核对当前代码；入口表不是固定架构事实。
- 缺少关联字段时，明确写“无法还原实例级流程”，只提供代码路径和独立观测；不靠相邻行或时间戳拼出执行顺序。无日志时仍保留五部分结构，标记观测图与频次缺失，不用代码模拟日志。

### 为本次分析创建报告

- 同一流程、相同代码版本或相同日志再次分析，也创建新报告；“再分析一次”“按最新代码重新生成”不表示覆盖旧报告。可读取旧报告作历史参考，但重新核对本次代码和日志，不沿用未经核对的结论。
- 项目内默认路径为 `docs/behavior-models/<flow>--<YYYYMMDDTHHmmssZ>.md`，例如 `knowledge-save--20261005T044600Z.md`。从本次分析开始时间生成 UTC 时间戳（`Z`），将流程名整理为不含空格、路径分隔符的短文件名；不要照抄示例时间。
- 用户指定目录时，在该目录使用上述命名；指定完整文件路径且尚不存在时使用该路径。指定文件已存在时，在其原文件名后、扩展名前追加本次时间戳。路径仍重复时依次追加 `-02`、`-03`，直到取得新路径；同一秒内重复分析也不能覆盖。
- 用排他创建方式保留新路径（如 Python `open(path, 'x')`）；遇到已存在错误就选择下一个名称，不截断、清空或覆盖已有文件。之后只完善本次创建的文件；同一次分析中断后继续，可沿用本次文件，不因每次补写再建一份。
- 仅当用户明确要求修改、补充或覆盖某份已有报告时，读取并更新该报告；仅指定一个已有路径不足以推断覆盖授权。
- 在模板中记录报告编号（文件名去掉扩展名）、本次生成时间（含时区）和实际保存路径；引用旧报告时注明其路径及用途。缺少日志仍新建报告并标明证据缺口。

## 2. 建立证据账本

给证据分配稳定 ID：C01 为代码，L01 为日志，I01 为推断。代码引用包含 commit、文件、行号或函数与精确片段；日志引用包含文件、行号、时间窗口、实例字段、事件/状态和匹配模式。共享报告只摘录脱敏必要字段，不包含 API Key、原始录音或无关正文。

沿入口查调用、数据读写、事务边界、分支、重试、取消和外部交互。只收集本流程实际读取/修改的对象。对同义方法/状态建立“候选业务名 → 原始技术名 → 证据 ID”对照；不同含义的同名事件不能强行合并。

将证据分为四类：

| 类别 | 判定 | 呈现位置 |
| --- | --- | --- |
| 当前已观测 | 现行代码支持且日志发生 | 主活动/状态图及实例时间线 |
| 冷路径 | 现行代码支持但窗口内未观测 | 附录，不并进观测主图 |
| 历史或旁路 | 日志发生但与现行代码不符、版本无法对齐或绕过选定流程入口 | 单独附录，说明不匹配原因 |
| 推断 | 缺乏直接证据或业务含义未确认 | 显式标 I 编号及待确认问题 |

日志有序不等于业务因果。优先使用同进程 sequence、parent span 和明确的调用/提交依赖；跨进程时钟偏差、并行分支和无父子关系的 span 用偏序/并行表示。断档、丢事件、重复导入、重试、多进程以及截断都要标记。去重只用可靠事件标识（如 process_id + sequence），不要把同名重试合并。

## 3. 选择样本并计数

在明确的窗口内按完整且可关联实例分组，计算各路径出现次数。选择观测中频次最高的完整路径作为主路径并报告分母、排除数和排除原因；只有单个实例时称“样本路径”，不称系统常态。没有足够完整实例时，不声称找到了高频主路径。

选择有证据的异常实例，分别跟踪失败、重试、恢复、取消和补偿。失败后再调用不自动等于补偿；只有撤销/抵消已完成业务效果且有代码与日志证据时才叫补偿。没有异常/补偿日志时，保留第二张图的位置并写证据缺口，不伪造分支来满足图数。

状态转移需要源状态、目标状态和同一对象的关联证据；不能把 span 的 started/succeeded 当成业务对象生命周期。频次注明按实例、尝试还是转移计数，重复尝试保留；日志覆盖不全时只给观测次数，不估计全局比例。

## 4. 按固定顺序输出

使用 [报告模板](references/report-template.md)。先写短的范围/版本/完整性说明，随后严格按以下五部分输出；附录放在最后。

1. **类图**：只收录选定流程读写的对象。写名称、关键属性和组合/对象引用/仅 ID 的关联；标出“持久化镜像”与“领域对象候选”。不展开全库表或纯技术类。
2. **活动图**：主路径和有日志证据的异常/补偿路径分图。用 Mermaid flowchart 的 subgraph 表示用户、本系统模块、外部系统泳道；业务动作、判断条件、并发/结束与证据 ID 都要可追踪。不把冷路径混进主图。
3. **状态图**：只针对真正有生命周期的对象，使用 Mermaid stateDiagram-v2。主图仅含代码允许且日志出现的转移，标观测次数/相对频次与证据 ID。没有合格对象则明确说明，不创造生命周期。
4. **事件风暴时间线**：选择一条完整实例，列命令（触发者/入口）、已发生事实、涉及对象/候选聚合或外部系统及原始技术名。把技术诊断事件明确标为技术事件；候选领域事件的业务含义未确认时标推断。保留并行/未知顺序。失败后的补偿单独一条时间线；未观测补偿则直接说明。
5. **聚合候选与待确认清单**：每个候选列内部对象、推测的不变量、证据和反证，全部称假说。同一事务是强证据，同一 trace 共同修改只是弱证据，对外只传 ID 是边界线索，都不是业务边界证明。待确认仅写代码和日志无法回答的业务含义、角色、禁止规则或边界问题；技术事实先自行查证。

每个步骤、判断、转移和事件均带证据 ID，账本能回到原始来源；无法指回的明确标推断，不进入事实状态转移。图只展示一种关系，较宽图改成自上而下，短标签，细节放表中。不依赖 HTML 标签或远程脚本。若所在环境没有 Mermaid 渲染能力，交付 Mermaid 源码并说明未渲染验证，不声称检查了图片。

## 5. 交付前核对

- 五部分顺序固定；主/异常路径、正常/补偿时间线各自独立；缺证据的部分诚实留空并说明缺项。
- 图中每个业务断言能定位到证据账本；计数能回到去重后的样本集合和分母。
- 代码有日志无的转移只在冷路径附录；日志有代码不符的记录只在历史或旁路附录。
- 不把调用成功写成任务完成，不把浏览器上报完成写成扬声器已发声，不把未观测写成未执行。
- 不输出重构建议、理想规则或跨全库模型，除非用户另行要求。
- 核对实际路径与本次报告编号一致，已有报告未被改写；交付本次文件的准确路径或链接，不只给目录或旧报告链接。不提交原始私密日志。引用当前分析 commit，使后续代码变化不悄悄改变报告含义。
